# 评审闸门：谁通过、怎么通过、不过怎么办

> **何时读**：每一步收敛完、准备请人复审之前。
> **闸门数量与阻塞性读 `../PROJECT.md §五`**，本文件只定义"怎么过"。

## 铁律：自检通过 ≠ 闸门通过

AI 完成本步收敛后，**只能报告"待复审"**，不允许自己推进进度计数。
**必须等到显式表态**（"通过" / "可以" / "下一步"）才推进。

**适用场景不止闸门收尾**——任何你说"请审 / 过审 / 推进"之前都适用，包括修订完成后请人复审的时刻。

**反模式**：把"我已经检查过没问题了"当成通过；把对方的沉默当成默认同意；
把"嗯"这类非表态当成放行。

## 四道闸（默认档案，可在 PROJECT.md 改）

| 闸 | 名称 | 收敛了什么才请审 | 他在审什么 |
|---|---|---|---|
| **G1** | 探索确认 | 七要素收齐、逐层 why 追到真问题 | 方向对不对、是不是真问题 |
| **G2** | 影响面确认 | 类型判定 + 波及面盘完 | 有没有漏掉会被牵连的地方 |
| **G3** | 方案核对 | 页面/能力改动清单逐条实查完 | 每一处改动落点对不对、要不要做 |
| **G4** | 收口评审 | 五段成文组装完 | 表达清不清楚、能不能被验证、有没有混进实现细节 |

`review_phase` = 已过的**阻塞型**闸门数；`status=ready` 要求它等于阻塞闸总数。

## 每道闸都要跑的三项贯穿复审

### 1. 占位健康度（风险刻度，不是硬卡线）

| 等级 | 触发 | 行为 |
|---|---|---|
| 🟢 | 都在阈值内 | 一句"占位健康" |
| 🟡 | 触预警阈值 | 列风险占位 + 影响 + 建议，**通过但提示，不阻断** |
| 🔴 | 触高风险阈值 | 强提示 + 风险后果，**需显式"已知风险继续" + 双留痕** |

| 维度 | 🟡 | 🔴 |
|---|---|---|
| 单步占位数 | > 5 | > 10 |
| 全需求累计未解占位 | > 15 | > 30 |
| 等人拍板时长 | > 3 天 | > 7 天 |
| 等客户 / 等外部时长 | > 7 天 | > 14 天 |

输出格式：

```
[占位健康度]
  等级：🟢 / 🟡 / 🔴
  触发项：等客户 3 个，最长 21 天（预期解除：客户访谈 6-15）
  风险后果：{评估}
  建议：{先解 X / 与下步无依赖可继续}
```

🔴 继续必须**双留痕**：流水账一条（已知风险继续 + 原因）+ 元数据里的占位健康度节。

### 2. 查证留痕复审
本步发起过的查证，逐条核「收益」问答得出吗（见 `evidence.md §四`）。答不出的 = 白查，下次别挖。

### 3. 待确认项分档复审
本步新增的待确认项逐条过 `ask-or-not.md` 判断树——
**途中"想先记下来"的项，到写表时最容易被顺手抄进去**，而每多一条 🔴，收口就多一道必须拍板才能过的闸。

## 闸门处置

### 通过后
1. 推进 `review_phase`
2. 流水账记一条（状态变化行写 `review_phase: N → N+1`）
3. 汇报下一步做什么

### 未过
**按打回的粒度重做，不重跑整步**：

| 打回类型 | 处置 |
|---|---|
| 某条结论不认可 | 只改那条 + 它的派生，不重跑本步 |
| 方向错了 | 回上一步重做，**并说明为什么之前判错**（下次才防得住）|
| 信息不够判断 | **这是我的问题不是他的**——补齐背景重新请审（见下「背景关」）|

### 请拍板前过两关

决策类输出比陈述类多一层要求：

| 关 | 自检 |
|---|---|
| **翻译关** | 这句里有没有只有我懂的记号缩写或环节名？影响面别写 X/Y 估算记号，只说"确定要做的 N 个模块 + 可能牵连的 M 个" |
| **背景关** | 他手上的信息够不够判断？让他决定"是否跳过某个分析环节"，**先一句话讲清那环节产出什么、为什么这次这么建议**，再抛选择 |

两关任一没过 = 让人拍板却没让人看懂，**必被退回**。

## 轻量需求的合批快车道

**治什么**：对小需求，**阻塞停点的数量本身就是耗时大头**——每一次停等都比一轮轻量分析贵。

**入口判据**（探索期即可预判）：单一用户故事 + 复用既有 + 无新概念/流程/页面 + 改动 1-2 个入口。

三点改动：

1. **追问攒批**：豁免"一次一问"——关键缺口**一次问齐**，
   规模控制在他一屏内能逐条答完，不是把想到的都堆成长清单。
2. **连跑 + 合批请审**：G1 → G2 → G3 连续跑完不停，攒到**一个停点分三层请审**。
   首行声明：「本需求命中轻量判据（{依据}），已连跑三步，下面分三层请审——
   **任一层不过可单层打回，我只重做该层及以后**」。
   **三个闸的检验项一项不少、拍板项同批弹，变的只是呈报时机。** 他表态哪几层过就推几步。
3. **降级出口**：连跑中发现不满足轻量判据（冒出新页 / 新概念 / 跨域 / 拆出多条故事）→
   **立即停在当前步**，按标准逐闸请审已完成的部分，首行说明"已退出快车道：{原因}"。
   他任何时候说"一步步来" → 切回标准节奏。

**快车道成立的根据是代价不对称**：连跑三步对小需求都是轻量分析，
方向判错他在合批第一层打回、与逐闸打回等价——
**省的是他的两三轮停等，赌错赔的只是我的一轮轻量分析。**

## 待确认项的收口门禁

`🔴 待拍板` 是**收口 / 提交的阻塞项**：状态推进前要么答（答复落「已定事项」，处置转 ✅）、
要么显式弃权（转 ⏭ 并记流水），**不得留 🔴**。

`⏳ 待客户` **不挡**状态推进（等客户回话是流程常态）。

> **为什么不给"推迟"这一档**：推迟 = 悬住，正是"需求都提交了还留一堆待确认、影响开发"的病根。
> 需拍板的项现在就得清——**答或弃权，二选一**。

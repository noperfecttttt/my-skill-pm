# 原型生成

## 它是什么、不是什么

**是**：给业务方和客户看的、浏览器打开即用的高保真演示。
**不是**：可运行的产品代码、不接真实业务接口、不做登录态注入。

## 开工前

1. 读 `../pm-kit/PROJECT.md §三` —— 用什么组件库、怎么引、有没有页面类型规范、几个端。
   **填「无」也能画**：没有组件库时用语义化 HTML + 一套克制的 CSS，方法论照样成立。
   **不要因为没有组件库就跳过原型。**
2. 读 `references/principles.md` —— 信源纪律 + demo 验证力（**这两条决定原型有没有用**）。
3. 读需求的改动清单与各页规格——**原型的分母是清单，不是你的印象**。

---

## 五步

| 步 | 做什么 |
|---|---|
| **1** | **解析页面清单**：从改动清单取全部落点，逐条确认"这一页画不画、画成什么" |
| **2** | **取现状基线**：改造类页面逐页取真实页证据（`PROJECT.md §二`）；**禁用一页推断其余** |
| **3** | **画**：概览页（恒第一、恒存在）+ 各业务场景 |
| **4** | **标注改造点**：红点 + 气泡，只标本期真改动的地方 |
| **5** | **自检 + 实测**：跑 `references/self-check.md`，浏览器真打开逐页点一遍 |

---

## 恒定产出两件事（与任何条件无关）

1. **原型文件一定产**；
2. 其中的**「需求概述」页一定有**。

"不画界面"说的是不画界面，**不是"这个需求不需要一份能看的交付物"**。

**跳过原型的理由都不成立**——"纯后端改动 / 无界面变更 / 改动很轻 / 标注图已说清"都不算：
**原型的读者是客户与测试，不只是研发。**

只有一种情况只出概览页（见 `references/overview-page.md`）：
整单没有任何页面条目，或对方明确说本单不画页面场景。

---

## 三条硬纪律

### 1. 每个元素都要能溯源
每个页面 / 字段 / 交互 / 文案都要能答"这是从哪来的"，答案只允许两种：
**该端真实页某处**，或**需求某条**。答不出 = 凭印象编的，删掉或去补信源。

### 2. 先判这个 demo 要验证什么，再让它真验证得了
把页面长相画出来、每页塞一份写死的示例，演示的是"长什么样"，
**对核心价值是盲的**——看着"做了"，评审只能脑补，零验证力。

### 3. 改完原型要回写规格
从第 2 轮起，他的每一次调整都是**对着原型**提的。
他指着页面说"这里不对"，改的是原型，**规格必须跟着改，顺序不能反**。
（详见 `../pm-requirement/steps/4-demo-loop.md`）

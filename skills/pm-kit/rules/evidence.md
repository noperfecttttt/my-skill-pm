# 证据与信源：宁缺勿编 · 查证准入 · 作用域纪律

> **何时读**：写任何一句"平台/系统**现在**是这样"的话之前；发起任何一次查证之前；
> 把查到的东西落进产物之前。三个时点各管一段，缺一段就会出那种**读起来完全合理、但没有任何依据**的句子。
>
> 本文件依赖 `PROJECT.md §二 事实信源分级`——那张表说"去哪查"，本文件说"怎么判、能断言到哪一层"。

---

## 一、宁缺勿编（与其他规则冲突时以本条为准）

无真实输入时**显式占位 + 责任人 + 预期解除**，禁止推断填充。

**"看起来合理的默认值"也是推断填充，而且最危险。**
描述现有功能、或对现有功能的任何改动时，每个字段 / 属性 / 规则只能三选一：

1. 有出处 → 写，并挂出处；
2. 暂无但能查 → **立刻去查补上**；
3. 查不到或属人的决策 → **显式占位**。

`≤50字` / `默认必填` / `支持批量` 这类"行业常见值"最像真的、最容易被信任，恰恰最该核实或占位：
**留空会被追问，假值会被当结论传到开发，照着建库建校验。**

> **挂出处 = 可验收。** 无出处的具体数值 / 字段属性 / 规则，复审默认按编造处理打回。

## 二、写"现状是这样"之前：三条判据

### 1. 结构看后端、现状功能看前端，各有其源不可互推

| 要判的事 | 用什么信源 | **不能**用什么 |
|---|---|---|
| 有没有这张表 / 字段 / 接口能收什么 | 后端契约（见 PROJECT.md §二）| — |
| 这一页现在长什么样、某元素在不在 | 真实页 / 前端源码 | ❌ 后端契约（它不承载前端现状）<br>❌ 常识推断 |
| 某能力前端放出来没有 | 同上 | ❌ "后端有这个字段，所以前端应该有" |

**后端能收 ≠ 前端已放。** 这类"后端早支持、前端锁着没放开"的需求工作量主体全在前端，
绝不能因为后端字段存在就判「现状已有、几乎不用做」。

### 2. 逐端逐页各自取证，禁用一端证据外推另一端

写"另一端也是这样""另一页同样如此""两端逐条一致"之前，**那一端/那一页自己得有证据**。
两份原型各用一套演示数据时，它们不构成跨端逐条比对的证据。

### 3. 手上的材料不含该元素 ≠ 该元素不存在 / 是普通形态

抓过的那个样本里恰好没有这类数据（没有分组、没有长值、没有某种类型），**那叫证据缺位**，
不叫"它就是常规样子"。

### 证据缺位时的三个合法出口（挑一个，不许硬写）

1. **标未取证**——写"现状基线待实查"，别用确定语气；
2. **交研发核**——写进开工自查项，并注明"若与此不符属范围变化、须回报"；
3. **问人**——一句话问清，比写错一句便宜得多。

## 三、作用域纪律：断言的作用域不得超过信源的作用域

这是上面各条的**总纲**，也是最容易在"自己很确信"时违反的一条。

| 你读的是 | 能证明 | 不能证明 |
|---|---|---|
| 某一个租户 / 机构的运行时配置 | **该租户**看到什么 | **产品**有什么（配置可能被单独改过）|
| 随版本发布的默认配置种子 | 产品级默认有什么 | 某租户现在是什么 |
| 派生的配置件 / 中间层 | 取值域、权限码 | 这一项**存在**（配置不是界面）|
| 某一次导出 / 截图 / 一条数据 | 长什么样 | 哪些字段固定、哪些是动态生成的 |

**两个方向都要防**（实战里两边各犯过一次）：

- 信源是派生层，断言下到"这个字段的真名是什么"；
- 信源是单租户运行时，断言上到"产品级有没有这一列"。

> 🔥 **减法比加法危险。** 拿运行时配置做的断言产出的往往是**减法**（删列、删权限码）——
> **加错了下游会发现，删错了下游只会觉得"本来就没有"。**

**判"某租户被改过"，必须先取产品级默认做基线**，否则会把**版本演进**误记成**租户改动**。

**一条反例**：「权限码存在 ⇒ 对应功能存在」**不成立**——配置里常有无人引用的孤悬码。

## 四、查证准入：动手查之前先过五问

> 上位总纲：**技术疑问不仅不问、不标、不写，也不为它去查。**
> 工具就在手边、查起来很容易，都不是发起查证的理由。

| 问 | 通过标准 | 典型不通过 |
|---|---|---|
| **收益** | 说得出这次查证的结论会**改变需求里哪一句话**（哪条规则 / 哪条故事 / 范围 / 成本判断）| 答不出 → **停手，不查也不记录**。"研发要用"不算（研发手里有代码，比你准）|
| **必要性** | 当前这一步的必填内容卡在缺这层信息 | "顺便看看" / "防漏看" / "查了更扎实"；**「模板里有张表要填」也不算**——那张表是收纳已挖到的东西，不是查的理由 |
| **最小化** | 选最少节点 + 最轻读法（索引 < 摘要 < 全文）| 索引已经够却去读全文 |
| **当步性** | 此信息不能推到下一步 | 下一步本来就要读它 |
| **替代性** | 已确认无更轻路径 | 没试索引直接读全文 |

**为什么「收益」摆第一问**：后四问都是许可式——问"允不允许查"，而动手那一刻总编得出一个理由
（最常见的托词是"确认可实现性"，挖回来的技术事实大半支撑不了任何需求结论）。
**收益问的是"查了有什么用"，答不出就没有查的意义，不必再问后面四问。**

任一不通过 → 三档处置：**A** 改更轻路径重试（自主）｜**B** 挂占位推到下一步（自主）｜**C** 升级问人（给 ≥2 个选项 + 各自后果 + 推荐）。

## 五、落纸判据：翻译不成业务话的，这次查的收益就是零

查到的东西要落进产物之前，**先把结论翻译成业务级陈述**：

- ✅ 「创建人这个信息记录上本来就有，可以拿来判定」——业务话，落得下（它支撑"这需求可实现"）
- ❌ 「`xx_table.create_user_id`，现有索引不含按人查的维度」——只能原样写技术名才说得清

**只能原样写技术名的，说明这次查证对需求判断的收益是零 → 不记**（下次也别再挖一遍）。
典型这一类：表名与字段物理名、索引结构、端点全路径与报文、状态码与锁、内部实现分层。

> 它与「查证准入」互为对偶：**准入管"要不要查"（事前），落纸管"查了怎么写"（动笔时）**。
> 事前判断能被一个"业务理由"绕过，翻译这一步绕不过去——翻不出来就是白挖一趟，白挖过一次，下次自然不挖。

## 六、技术标识符必须有出处

凡写进产物的**字段名 / 列名 / 接口端点 / 权限码 / 表名**，落笔前回原始材料里 `grep` 一次。

- **禁止把中文名直译回英文当技术名。**「开始学习时间」→ `startStudyTime` 看着天经地义，
  实际那张表里叫 `startTime`。直译产出的名字**长得非常像真的**，这正是它危险的地方。
- **在别的模块里搜到不算数**——同名字段跨模块串味是这类错的主要形态。
- **物理名不保证唯一**，认字段用稳定键，并在旁边注明"物理名不唯一"。
- **原始材料在手却凭印象写**，是这条要治的根。抓取件、配置件、接口件只要在手上，
  **就没有"拿不到、只能推"这个选项**。

**为什么这类错零反馈**：需求负责人不看技术附录；评审的人手里没有原始件做比对基准；
机器不核；只有最下游研发按名去找时才炸——而那时往往已经静默拿到了另一个同名字段。

**收尾自检**：这份件里的每个技术标识符，**我能说出它是从哪一行抄来的吗？** 说不出 = 没核。

## 七、名字要钉到真实的东西上

用户口中的「详情页 / 跟踪页 / 导出页」是**平台内部指代，不是字面通用概念**，同一个名字常多义。
**多义就是必须澄清的信号**，不许挑一个通用义往下写。

做法：先复述「我理解这名字 = 【某页】，上面现有【某些按钮】，你要的改动落在【某元素】上」，
确认后再展开。**入口 / 按钮级需求对指代准确特别敏感——错一个名 = 整块规格返工**（不像字段级只错一处）。

**同一个动作可能挂在多个承载位**：工具栏 / 行内常显 / 行内「更多」收起下拉 / 批量态顶栏 / 右键菜单。
下"此页没有 X"这种**负面结论**，必须穷尽承载位才能下；收起态的菜单项要主动展开或读隐藏 DOM
（截图和无障碍树只反映可见元素）；逐行核并给计数（"10/10 行都有"），不拿第一行代表整列。

# 步 1 · 探索真问题（七要素 + 逐层 Why + 伪需求判定）

> **必读**：`../../pm-kit/rules/ask-or-not.md`（决定哪些根本不该问）
> **产出**：`process/steps/1-explore.md`

---

## Phase A · 识别来源与类型

来源是**客户提的**还是**主动规划的**？两者的举证责任不同：
- 客户提的 → 要追到真实场景与频率；
- 主动规划的 → **必须填「场景验证证据」**，否则它就是一个想法，不是需求。

## Phase B · 起草第 1 稿

先用手上的材料起一稿，**不要空着去问**。有稿再问，对方是在**纠正**（便宜）；
没稿去问，对方是在**从零口述**（贵，且他会觉得这活是你推给他的）。

## Phase C · 七要素追问（核心）

### 启动前必做：业界共性反查（自答，不问人）

先想清三件事，想清楚的就别问了：
1. 同行产品普遍怎么解这个问题？
2. 这类需求的标准形态是什么？
3. 按常识推，哪些子问题的答案是确定的？

> 七要素是**取材清单，不是逐项念的问卷**。能从行业常识推断的，自己答。

### 七要素

| 要素 | 采集什么 |
|---|---|
| **Who** | 谁用。**拆二维**：**身份差异**（账号形式 / 可见性 / 计费归属 / 数据隔离）+ **能力差异**（可做哪些动作 / 可拿到什么反馈 / 计不计入统计——逐项确认）。能力一致 → **显式写「能力与正式用户一致」** |
| **What** | 要什么。一句话需求 = `[场景定位] + [核心动作]` |
| **Why** | **必内嵌逐层 why**，追到真问题清晰为止，**不设轮数上限** |
| **When** | 什么时候发生、多频繁。**频率为零 = 伪需求信号** |
| **Where** | 落在哪个页面 / 入口 / 环节 |
| **Pain** | 现在不做的话，谁在承担什么代价。能量化就量化 |
| **Boundary** | 范围边界。**模糊范围词必先澄清维度**（见下）|

### Boundary：模糊范围词必先澄清维度

对方说"先做个简版 / 轻量版 / 一期只做核心"时，**先问清是哪个维度的轻**：

| 维度 | 含义 | 后果 |
|---|---|---|
| **功能维度** | 少做几个功能 / 场景 | 交付范围变窄 |
| **工程维度** | 功能全量，只是少改代码（低侵入）| **范围不变**，只是影响面收窄 |

**两者后果完全不同**，混着答会让整份需求的范围判断错位。

**依赖某套专业方法论时，方法论自身的禁用边界是硬约束**（不能因为"我们这次简化一下"就越过）。

### 追问规则

- **一次一问**：每轮只问一个最关键缺口，等回答再问下一个。
- 问之前先过 `ask-or-not.md` 的三格——**填得出"我的答案"就别问了**。
- **问的是业务，不是实现**：价值 / 角色 / 流程 / 边界 / 规则。

### 追问终止条件（任一命中即停）

1. 七要素都有了可用答案（含显式占位）；
2. 再问下去只能得到实现层答案；
3. 对方明确说"就这些"。

## Phase D · 伪需求判定（七要素全填完后一次性进入）

**不要边填边判**，会打断追问节奏。任一命中 → **不进影响面分析**，走对应处置。

| 类 | 判据 | 处置 |
|---|---|---|
| **① 理解错位** | 客户给的是**方案**不是问题；或假设本身错了 | **改写真问题（改 Why）**，回 Phase C 重做 |
| **② 场景空洞** | 描述是对的，但没有真实场景 / 频率为零 | 客户需求 → **拒做挂账**；主动规划 → **先验证场景**，验完回 Phase C |
| **③ 路径错位** | 需求真实，但不该走这条路解决 | 现有功能能承接 → 闭环到现有；配置/培训能解决 → 转客户成功；只有一个客户要 → 走定制交付 |

命中时产物走**精简结构**（真问题改写 + 已追到的七要素 + 判定 + 处置结论），
**不走完整七要素**，状态挂账。

---

## 复合需求拆分

一份输入里其实装了多个需求时要拆。**"相互独立"判据四维，任两条不满足即视为复合**：

1. 用户目标不同；
2. 角色不同；
3. 可以分别上线、互不依赖；
4. 砍掉其中一个，另一个仍然成立。

拆分后各自建档，用 `relates_to` 互相引用。

## 产物结构（两层，别多写）

```markdown
# 需求探索

## 📌 需求一页（给他确认的只有本节）
### 真问题（Why 追根后）
### 七要素摘要

## 工作底账（供后续步骤取数；复审可不读）
- 伪需求自检：① 理解错位 ② 场景空洞 ③ 路径错位 —— 各一行未命中/命中
- 查证留痕（收益 + 结论两行）
```

> **落盘纪律**：过闸要答的是"真问题对不对、范围认不认"——他读的就是「需求一页」那两节。
> 底账只收**下游要取的结论行**，推导过程（业界反查的自答、伪需求判定的论证）**留在对话**。
> 空项删行，不写"无"占位。

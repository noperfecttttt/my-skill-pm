# 步 5 · 收口成文

> **必读**：`../../pm-kit/rules/final-audit.md`（终审电池）
> + `../../pm-kit/rules/item-admission.md`（条目回筛）
> **产出**：`deliverables/requirement.md`（五段）+ `deliverables/page-specs/*.md`

**三段式：检查 → 补产 → 组装。** 顺序不能反——先知道缺什么，再补，最后才组装。

---

## 第一段 · 检查（先列缺口，别急着写）

逐项跑，**列成一张缺口表**，不要边查边补：

| 检查项 | 判据 |
|---|---|
| **规格分册完整性** | 改动清单每一行都有对应分册吗？分册数明显多于真实页面数吗（多了 = 混了维度）|
| **四件齐** | 每页规格：元素 / 文案 / 交互 / **业务逻辑**——最后一件最易漏 |
| **条目回筛** | 用户故事、业务规则逐条回过 `item-admission.md` 的尺子了吗 |
| **规则来源四问** | 每条规则答得出"从哪来"吗（现状 / 规范 / 纠正我 / 本期新定）|
| **编号连续性** | 有断档吗（断档 = 删过条目但没回头收拾）|
| **定义/引用形态** | 每个编号全包只有一行定义行吗 |
| **待确认门禁** | 还有 🔴 吗（ready 前必须清：答 或 显式弃权）|
| **约束账本** | `.tmp/constraint-ledger.md` 最后一列有互斥警告没消解吗 |
| **占位健康度** | 等级是多少，🔴 的要不要先解 |

## 第二段 · 补产

按缺口表逐项补。补的时候：

- **新立条目照样过准入**——收口期最容易为了"填满模板"而硬凑；
- **模板里有张表要填，不构成去查证的理由**（那张表是收纳已挖到的东西）；
- 补不出来的**挂占位**，不编。

## 第三段 · 组装五段

按 `../../pm-kit/templates/requirement.md` 组装。

### 组装纪律

1. **载体唯一**：同一个事实只在一处定义。
   概览是**纯提炼下游、零新信息**；规则定义在各页规格，公共节只放按类聚合的索引。
2. **按需节没内容就整节不出现**（连标题一起省），不写"无"。
   问的是**事实题**："本期有没有改 X"，不是"要不要写 X"。
3. **概览的「核心业务规则」只放支柱**——改动入口 / 核心痛点解法 / 落地前提。
   每条 = 编号 + **一句自足业务钩子**（不翻别处也能看懂它在业务上解决什么）。
4. **全文禁裸编号引用**：这份文档里没有地方展示编号对照表，读者看到无处可查。
   流程图节点只写"页面名：做什么"。
5. **只写现状，不写过程**：`拍板|推翻|改回|曾定|被否` 在正文里 grep 应为 0。

### 形态 degrade（按交付清单的类型列判）

| 类型列 | 收敛 |
|---|---|
| 全是 `非页面·*` | 无界面需求：不铺页面交互档位；概览的「页面地图」换成「对接关系一览」 |
| 全是 `页面·报表` | 报表需求：公共节只写导出行为 / 空态 / 数值口径，不铺弹窗抽屉档位 |
| 其余 | 混合，不 degrade |

**照实标类型列**——标错了整份文档的章节集就跟着错。

## 收敛闸门（进 G4 之前）

**跑完 `final-audit.md` 的终审五步**，逐步留证据：

1. 全文逐节通读（**含摘要 / 派生层**——它们最容易停在旧版本）
2. grep 不变量电池（被推翻的旧词全为 0）
3. 需求 ↔ 原型双向核对
4. 引用完整性（无悬空编号）
5. 摘要层逐条对照

**自查姿态**：宣告完成前自问——
> **"如果他追问『确定一点问题都没有？』，我能拿出哪条 grep 输出作证据？"**

拿不出 → 没查完，**不许宣告**。

**🛡️ G4 收口评审闸** —— 他审的是：**表达清不清楚、能不能被验证、有没有混进实现细节**。

---

## 过闸后

1. `status: draft → ready`，`review_phase` 推到上界；
2. 流水记一条 `状态推进` + 一条 `版本变更`；
3. 停点汇报里**建议下一阶段换新会话起跑**（两半理由都要说，见 `stop-report.md`）。

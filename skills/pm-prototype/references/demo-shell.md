# 演示壳：场景导航 · 场景分页 · 改造点标注

> 具体用什么组件 / 有没有现成模板，读 `../../pm-kit/PROJECT.md §三`。
> 本文件只定**形态与规约**——它们与渲染栈无关。

---

## 一、场景导航（侧栏）

把**变化页 + 不变页 + 新页**按业务动线串成完整流程，让人顺着点得下来。

| 规约 | 内容 |
|---|---|
| **首项恒为「📋 需求概述」** | 带分隔线与其余场景隔开 |
| **其余按业务动线排序** | 不按字母序、不按创建顺序 |
| **按钮文字纯文字 4–6 字** | 不加图标序号；技术标识另挂标签位 |
| **浅色主题** | 深色侧栏在客户演示场景显得突兀压抑 |
| **恒有收起 / 展开** | 收起后主内容区边距归零，看全宽干净页 |
| **导航 ↔ 页面清单双向对照** | 清单的影响页 / 新增页无一遗漏、导航项无一虚构、页名与清单**逐字一致** |

> 「需求概述」**不参与**双向对照——它不是业务页，不在改动清单上。

**实现上的通用坑**：导航是演示工具、不是业务界面，
把它放进业务应用的根容器内会被容器的溢出隐藏 / 层叠规则干扰导致点击失效——**放在应用容器之外**。

---

## 二、场景分页：状态演示必须拆独立场景

**禁止在页内放单选 / 开关让人点着切换演示状态。**

凡需要对比展示同一页面的多个状态 / 变体（已开通 vs 未开通、待处理 vs 已完成、
签名前 vs 签名后），**每个状态各生成一个固定状态的场景入口**，点进去就是那个状态。

- 入口命名**带状态后缀**（「创建鉴定·要素已开通」「创建鉴定·要素未开通」），一眼看出是哪个状态；
- 仍是同一个原型文件，靠导航入口实现，**不拆成多个文件**；
- **场景导航本身不算"页内切换"**——它是演示脚手架；被禁的是"用控件切换同一页的演示状态"。

> **为什么**：点着切换的演示，客户截图进汇报材料时只能带走其中一个状态，
> 而且演示现场他得先学会怎么切。

## 三、改造点标注（红点 + 气泡）

**只标本期真改动的地方。** 不标既有功能、不标"顺便提一下"。

| 规约 | 内容 |
|---|---|
| **形态** | 红点贴在被改元素旁，点击弹出气泡说明「改什么 · 为什么」 |
| **必须真能点** | **红点是评审动线的第一入口，"红点点不动"是高频死件** |
| **有开关** | 一个全局拨杆可整体隐藏标注，让人看干净页面 |
| **边缘处理** | 贴着视口右缘的元素，红点要能翻到左边，否则被切掉一半 |
| **嵌快照时** | 标注注入到快照内容里，用守卫防重复注入；改造点在长列表靠下时要滚动到可见 |

**改造点里的功能控件要克隆真实元素，不要手搓**——
手搓的假下拉、假操作链长得像但点不动，而**评审第一个点的就是它**。

## 四、需求说明不进界面

**原型只呈现真实产品会显示的内容。**

判据一句：**真实产品这个页面会不会显示这句话？不会 → 不进界面。**

| 禁 | 例 |
|---|---|
| 规则编号括注 | 「转码中不可预览…（BR-24）」 |
| 解释性灰色说明 | 「提交时快照…题库改题不影响此处展示」 |
| 页头说明标签 | 「××菜单（独立权限点控显隐 ｜ 统一汇总）」 |

**可保留**：改造点标记（红点）· 真实产品会有的帮助提示 · 演示壳本身。

**需求说明的去处**：写进需求文档与页面规格；原型里要留注解用 **HTML 注释**（不渲染），
不用可见文本。

**收尾 grep 自查**：可见文本里的规则编号、注解特征词，除注释外命中应为 0。

## 五、离线可用

**双击文件能打开就能看**是这份交付物的基本盘——
客户不会为了看一眼原型去起一个本地服务器，也不保证他网络能连上你的资源。

- 依赖尽量本地化；必须外链的走白名单（见 `PROJECT.md §三`）；
- 外链挂了**不能整页白屏**：关键渲染包容错，失败时退回可读的降级形态；
- 嵌入的真实页快照必须**自包含**（样式内联、图片转内嵌），
  否则相对路径按当前页解析 → 本地 404 → **页面自身版式缺失，而组件样式照常加载**，
  极易误判为"还原对了"。

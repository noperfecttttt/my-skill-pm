## 三、待确认事项

> **相关方是闭集**：`决策人` / `客户` / `外部团队` / `我方内部`。
> 「研发」「测试」不是合法取值——技术类未定项落附录的「研发开工自查项」，
> 研发换任一写法都满足的压根不产生（判据见 `../rules/ask-or-not.md`）。
>
> **判据**：这条要是不定下来，**改变的是需求本身，还是只是工时与回归范围**？只改后者 → 不在这里。
>
> **首列要自表述**——读的人不翻别的文件就能答。写「场景 → 卡点 → 建议」三段。
> ❌「字段口径待定」 ✅「发证书时同名员工分不清：只给姓名不给工号，两个"张伟"无法确定发给谁
>    → 建议按姓名+部门匹配，仍重名的挂人工确认」
>
> **依据核查列必填**——「已查 X、Y、Z，无答案」。**空着 = 这条不合格**：
> 需求里已有描述的事拿去问，只会被打回。

| 要定什么（场景 → 卡点 → 建议） | 相关方 | 处置 | 依据核查 | 影响范围 · 定位 | 预期解除 |
|---|---|---|---|---|---|
| {{ 自表述一句 }} | {{ 决策人 / 客户 / 外部团队 / 我方内部 }} | {{ 🔴 待拍板 / ⏳ 待客户 / ✅ 已定 / ⏭ 弃权 }} | {{ 已查 X、Y，无答案 }} | {{ 影响哪条故事或哪个规格 }} | {{ 时间点 }} |

> **ready 与 done 前本表不得留 🔴**：要么答（→✅）、要么显式弃权（→⏭ 并记流水）。
> `⏳ 待客户` 不挡状态推进。
> 治的是"需求提交了还留一堆待确认、影响开发"。

# 步 4 · 原型迭代（唯一主线）

> **必读**：`../../pm-prototype/SKILL.md`（怎么画）
> **本文件只管节奏**：怎么开局、每轮做什么、什么时候算定型。

---

## 为什么所有需求都走这条

**他是对着原型点头的。** 他确认的是页面，不是文档。

而画原型必然带出规格没写到的东西（控件形态 / 提示语 / 空态 / 点了怎么反应），
他之后的每一次调整也都是**指着页面**提的。

**无界面需求也走**——只换三处：确认单元从"页"换成"能力条目"、
原型只含概览页、逐轮改的是概览页那一节。**节奏一个字不变。**

> 无界面需求过去在原型里**一个字都没有**——客户手上没有任何可看的东西，面客只能空口讲；
> 测试也没有一处能看到整单要验什么。

---

## D0 · 首版

1. 按改动清单画出**全部落点**（页面 + 非页面条目在概览页列出）；
2. 概览页直用方案概述原文；
3. 每页起一份规格骨架（至少「一屏概览」+ 字段清单雏形）；
4. **自己先当一次用户走一遍**再拿给他看。

## D-loop · 每轮三个方向（顺序不能乱）

```
①  他说什么 → 先落成结构（规格 → 原型）
    他刚拍的话当轮落盘：字段 / 逐字文案 / 规则。
    落的是【新终态】，不是拍板过程——
    直接把规则改成新说法，别写"本轮拍了 X、原来的 Y 不要了"（轮次账目归流水）。

②  按规格改原型 + 即时自检
    基准 = 该页规格。改完自己点一遍。

③ ⛔ 改完原型再回写规格（原型 → 规格）  ← 最容易漏的一步
    ① 和 ③ 方向相反，两步都要有：
    ① 是"他刚说的话先落成结构"，③ 是"原型定下来之后规格去贴它"。
    【从第 2 轮起，他的每一次调整都是对着原型提的】——
    他指着页面说"这里不对"，改的是原型，规格必须跟着改，顺序不能反。
```

### 回写规格要回写三样

| | 回写什么 |
|---|---|
| **页面元素** | 新增 / 改动的控件、字段、入口 |
| **交互** | 点了什么、看到什么、什么条件下不一样（能立成验收场景的落验收）|
| **文案** | **逐字抄原型，禁转述**——有两个下游按字面取用：研发直接复制、定稿对账 |

### 反向那一半同办

**规格里写了、原型上没有的，当轮问他要不要画。**

- 不许默默留着（留着 = 研发照它开工，而他从没见过它）；
- 不许顺手删（= 替他砍需求）；
- 答不了的进待确认。

> **不管业务规则的覆盖**：数据同步 / 权限校验 / 计算口径 / 定时任务这些后台逻辑本就不上原型，
> 拿"原型上没有"当缺口会把大半规则误报成问题。**这条核的是页面元素与交互。**

### 轮末热记

**每轮结束前把本轮拍板落账**（他刚说完，一分钟级）。
结算时冷回忆必丢细节——而**口径是最贵的那部分**。

流水记一条 `迭代轮次`：本轮拍了什么（落到哪页）+ 待客户确认清单。

---

## 轮次暂停

等客户回话时标记暂停状态，**不硬推**。流水记清楚在等什么、预期什么时候有回音。

## 定型（循环出口）

三个条件同时满足：

- [ ] 他说"就这样"；
- [ ] 每页规格与原型**双向对齐**（①③ 两个方向都走完了）；
- [ ] 原型自检清单全过（见 `../../pm-prototype/references/self-check.md`）。

定型后进步 5 收口。

---

## 整单大改的出口

推翻量级达到"整个方案作废"时**不硬塞进轮次**——回步 3 重做方案核对与清单重构，
流水记一条分界锚，重构后的新方案即新的 D0 输入。

# 步 2 · 影响面分析

> **必读**：`../../pm-kit/rules/evidence.md`（现状怎么判、查证准入）
> **产出**：`process/steps/2-impact.md`
>
> **这一步的价值不在"列得全"，在"把漏项逼出来"。** 下面每一节都是从真实漏项里长出来的。

---

## Action 1 · 类型四选一

| 类型 | 判据 |
|---|---|
| **新功能** | 现有系统没有承接这件事的地方 |
| **增强** | 在既有功能上加能力 |
| **优化** | 体验 / 性能改进，能力集不变 |
| **缺陷整改** | 现状与既定规格不符 |

类型判错会让后面的深度档、闸门、成本口径全链皆错。

## Action 2 · 影响范围估算（软提示，可往后收窄）

给**两条线**，不是一个数：
- **X = 确定要改的**模块数；
- **Y = 可能被牵连的**模块数。

**Y > X 时要想清扩散依据**（数据耦合 / 入口共用 / 口径共享，三选一），推导不落盘。

> 给人看的时候**别写 X/Y 这种记号**，说"确定要做的 N 个模块 + 可能牵连的 M 个"。

---

## 必查的七个维度（每个都是从真实漏项长出来的）

### 1. 改既有功能：下"简单 / 只改一处 / 某端不涉及"结论前先读透

**信号**：需求动词是"改 / 加 / 挪 / 换 + 既有功能"，而心里冒出"这个简单""就改这一处"。

**规律**：查到第一个能解释表面现象的接口 / 字段，**不等于读懂了这件事**——那只是起跳点。
读到能回答下面四问才算够：

1. **完整链路**：从触发 → 落库 → 展示整条读通，不是命中一个接口就停；
2. **牵动哪些预先算好存着的数字**：进度 / 完成数 / 人数 / 达成率——**口径一变要跟着重算**；
3. **有没有要区别对待的子类**：系统自动生成 vs 人工配置、虚拟 vs 真实，别一锅端；
4. **下游连锁 + 各端形态**：判"某端不涉及"前**先去那一端真实页看一眼**——
   有页面就是涉及，不能凭"这是管理端功能"的直觉拍。

> **把"想明白了"和"验证过了"分开**——只有后者才配叫读够。
> 下游影响要么写进需求、要么明确问人，**不许用"以现状规则为准"一句甩给开发**。

### 2. 对偶追问：每个维度反手问一句"那反过来呢"

**元规律**：影响面漏项几乎都出在**只想了显眼 / 正向的那一面，忘了反问它的对偶面**。

有写入就有回读、有新增就有存量、有发布就有撤回、有显眼入口就有隐性旁路。

### 3. 存量 / 历史数据（在已有数据的功能上加配置或改结构时，**必查一行**）

影响面里**必须有一行专讲存量怎么处理**——哪怕结论是不迁移，也要写明"存量不动、原样只读"，
别通篇只有"新增 / 新建"。

**判存量工作量分两层，禁混为一谈**：

| 层 | 问什么 | 典型结论 |
|---|---|---|
| **配置 / 业务层** | 老字段 / 概念在新方案里还在不在？ | 在 = 迁移有明确靶点 |
| **数据存储层** | 底层结构变没变？ | "固定列" → "动态可配结构" = **老数据必须清洗迁移**，这是实打实的工作量 |

**两层结论常相反**（业务层"能对上"、存储层"清洗照做"），**别用左栏结论替右栏**。

### 4. 入口普查（给某操作 / 数据加控制时，**必查一行**）

**信号**：给某业务动作或数据加控制——权限点、状态、列、按钮、开关。

第一步**不是画那个按钮**，而是盘全"能触发这个动作的所有路径"。

> **从动作反查入口，别从页面正查按钮**——比逐页找按钮可靠得多。

隐性路径每次过一遍：① 模板 / 默认值预设 ② 上传 / 批量创建等开关 ③ 批量入口
④ 嵌在别模块里的入口 ⑤ 对外接口 / 机器对接。

**控制点下沉到"动作层"**：前端逐一显隐是必要的，真正兜底靠后端在每个触发动作前统一校验——
嵌入式和未来新增的入口自动被兜住，不必穷举界面。

产出「受控入口全覆盖清单」表：入口 / 位置 / 对应动作 / 无权限时的表现。

### 5. 既有页面能力族盘点（改既有页 / 列表的某个能力时，**必做**）

**规律**：同一页面上的**列、排序、筛选、导出、批量是一组联动能力**，
动其中一个常牵动另外几个（新排序要和既有排序互斥、新列要不要进导出、导出范围和筛选口径一不一致）。

**只盯需求明说的那一个点、不盘全这一族，就会一次次漏补、需求反复升版。**

1. **先产出"该页面既有能力清单"**——用产品里的**真实文案**（去现状页核实，不自造同义词、不靠印象）；
2. **拿本次改动逐条过联动**，每条**要么纳入范围，要么显式写"本期不涉及 + 理由"**；
3. **写"本期不做"前先核实那个能力是不是既有**——既有能力别误写成"不做"，否则要返工修正。

### 6. 端间能力差异：按目标端各自取证

**信号**：某功能在某端缺失要补齐，尤其伴随"另一端已经支持"或"后端应该有了"。

**也包括"在管理端配开关、用户端按开关变展示"这类一端配、另一端生效的需求**——
**生效端的运行页同样要单独取证**，别因落点像"配置在管理端"就只盘管理端。

### 7. 导入 / 导出双向过（带导入导出能力的业务，**任何模型层改动都要过**）

判据与清单见 `../../pm-kit/rules/final-audit.md`。这里只记一句：
**"不做导入导出功能" ≠ "改动不连带到导入导出"**。

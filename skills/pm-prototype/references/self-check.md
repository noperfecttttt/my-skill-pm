# 原型收尾自检清单

> **本清单即检查项全集。** 逐条核，任一未过立即修复再继续。
> 分三类：**覆盖型**（该做到的做了没）· **技法型**（怎么验得准）· **底线型**（原型能不能跑）。

---

## 一、覆盖型

- [ ] **断言核销全绿**：该页规格里的每个字段 / 规则 / 验收场景，
      在原型里都兑现了且**带证据**。任一未兑现禁止收尾。
- [ ] **导航 ↔ 页面清单双向对照**：
      清单的影响页 / 新增页无一遗漏、导航项无一虚构、页名与清单**逐字一致**。
      核对结果写进汇报（"导航 N 项：影响页 X + 新增页 Y + 不变上下文 Z，与清单对齐"）。
- [ ] **需求概述页已产且与载体同文**：该有的节一节不缺，且是载体原文**而非转写**
      （逐段比对，改写了措辞即回补原文）。
- [ ] **业务主线走得通**：每条主线沿页面清单从头走一遍，每步"用户需要什么"在对应页面上被满足。
      走不通 = 页面 / 动线漏了，回补。
- [ ] **可操作元素真能操作**：每个像按钮的地方都点一遍，无死文字占位。
- [ ] **反向核**：原型里每个肉眼可见的内容块，规格有没有定义？
      原型比规格多画的，**要么回写规格，要么从原型删掉**。

## 二、技法型

- [ ] **横切复查（多页时必做）**：逐页查完再**按属性横扫一遍**——
      同类组件跨页用法一致吗？同一术语 / 按钮文案 / 状态词跨页措辞统一吗
      （一个功能别这页叫"提交"那页叫"保存"）？同类交互口径对齐吗（删除都二次确认、空态都有占位）？
      > **逐页验收永远发现不了系统性漂移。分多批 / 多轮生成的漂移最重，这一轮横扫不能省。**
- [ ] **任务克制走查**：以目标用户身份逐屏问"这一屏我要决策 / 完成什么"。
      同屏堆多组长清单 / 操作平铺不收纳 = "内容很多但不好用"，回写需求做信息分层。
- [ ] **文案语域**：出现实现语汇，或单条文案折行 ≥2 行 = 语域错了，回改。
- [ ] **操作密度**：同页 ≤3 主操作；表格操作列可见按钮 ≤3，超出收「更多」；无一行平铺 4+ 按钮。
- [ ] **视觉异常先证伪自己**：查自己的布局和相邻元素实际渲染宽度，
      **别先归因浏览器 / 插件 / 环境**。

## 三、底线型

- [ ] 演示壳在业务应用容器之外，点击真生效
- [ ] 场景切换函数与导航高亮态互相同步
- [ ] 离线双击可打开；外链挂了不整页白屏
- [ ] 嵌入的快照自包含（样式内联、图片内嵌），无相对路径 404

---

## 四、浏览器实测（必做，所有原型交付前 · 每页必做）

**不许只凭代码自检。** 真开浏览器，逐场景核：

- [ ] **控制台报错 = 0**
- [ ] **真渲染无白屏**（读 DOM 断言关键内容非空，不是"看着有东西"）
- [ ] **交互真生效**：逐条对照需求里的交互词真点一遍，断言真响应
      （"不可取消"的断言要真拦得住）
- [ ] **红点标注真可点**：每个有红点的场景实点 ≥1 个，气泡可见且内容非空
      > 红点属标注层，不在功能断言的分母里——**不在这里点就没有任何地方会验它**。
      > "注入成功 / 静态合规" ≠ 可点。
- [ ] **逐场景截图**
- [ ] **移动端原型用移动视口跑**——桌面视口跑移动端 = 布局验证失真的假绿

### 断言清单怎么来

**从规格的字段表 + 交互说明逐条派生，禁读原型代码反推。**

> **自己实现自己出题必然放水**：规格写「点击提示文案」、实现做成悬停，
> 断言只查提示存在照样全绿——**账平、检查绿、货错三者同时成立**，缺的就是这一步。

**交互断言必须含两半**：**触发动作 → 预期反应**。只断存在性的交互断言不合格。

### 修订节奏

- **攒批再测**：同一轮反馈的多处改动**改完一批再统一实测**。
  逐处改逐次开浏览器核对，是把最贵的校验挂在最小的改动粒度上——修改慢的主因之一。
- **增量重跑省中间轮，不省最终门禁**：改完只重跑失败场景，
  但**最终仍须完整全量跑一遍**收尾。

---

## 五、修完即报

最终全量实测通过后**立即进停点汇报**。

**禁在汇报前插入任何自加的归档 / 整理 / 改名工序**——
实测截图留在临时目录原地引用即可，**原型本体就是视觉真相，影子相册只造语义污染**，
而他还得干等这道自加工序跑完才能结束会话。

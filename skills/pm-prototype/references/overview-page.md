# 需求概述页（恒第一项、恒存在）

## 为什么有它

逐页的改造说明只回答"这一页改了什么"，**没有任何一处回答"这个需求整体是怎么回事"**。

做成导航第一项而非浮层：**一整页装得下整单方案，且客户打开原型第一眼就在那儿。**

---

## 内容：直用方案概述原文，禁转写

整段照抄需求载体顶部的「方案概述」四节
（`../../pm-kit/templates/solution-overview.md`）。

> **转写必漂移，方案层只有一个信源。** 载体改了重新生成即跟随。

**载体四节一节不少**：

1. **背景与目标**
2. **方案与改动**——落点 · 怎么做 · 核心逻辑 · 改动点清单（**页面 + 非页面都列**）
3. **用户操作主线**
4. **本期不做**（按需，无歧义项则载体本身就没这一节）

---

## 非页面需求节

**非页面条目（对外接口、定时任务、平台配置）不占原型画面，只有在这一页能被客户看到**——
漏了就是整单看不见、面客讲不出来。

**标题按整单形态二态**：

| 整单形态 | 标题 | 位置 |
|---|---|---|
| **有**页面需求 | `本需求还包含（非页面需求）` | 排在页面相关各节之后 |
| **全是**非页面需求 | `需求详情` | **它就是整页主角** |

> **为什么换名字**：这类单子的交付物全在这一节里，
> 还叫"本需求还包含"等于把主角说成附加项、把整单核心藏进附属位置。

**逐条按四行写**（内容直用各能力规格原文，禁转写）：

1. **什么时候发生**
2. **做什么**
3. **在哪能看到结果**
4. **出问题或边界**

**接口类要展开到详细需求，且折叠块默认展开**：
摘要四行 + 一个折叠块，块内直用接口规格原文——
为什么做 · 跟谁对接 / 传什么回什么 · 每个数怎么算 / 什么场景什么时候一次多少条 / **还没和对方定下来的**。

> **为什么默认展开**：折叠的唯一收益是保住整页扫读性，而右侧锚点已经在做这件事了；
> 代价却是把整单最核心的交付物藏在一次点击后面。

---

## 全局规则节（按需）

影响 ≥2 个页面 / 能力、或整单级跨业务才成立的规则。
逐页说明只讲本页，**这类规则在原型里没有别的地方能承载**。

**不收什么**：适用范围（"配置端 PC、用户端 PC+移动"）、现状不变声明、实现手段、
"本期不做但相关"的——前三类归全局前提或技术附录；最后一类要过「本期不做」自己的准入。

**合格条目为 0 → 整节不产**（不留空标题、不写"无"）。

---

## 准入判据（非页面节 / 全局规则共用，一条）

> **这一条如果不写，测试会不会漏测一个场景？客户会不会在演示会上问"这个怎么办"？**
> 两个都不会 → 不进这一页。

**读者是测试和客户，不是研发**：接口报文字段、配置项编号、日志逐列清单这类**只有研发需要的**，
留在各自规格与技术附录。页脚给一行说明把这条边界讲给客户听，省得他以为原型里就是全部。

---

## 版式硬要求

| 要求 | 为什么 |
|---|---|
| **表格全展示：不定高、不悬停** | 这一页**不是在模拟产品界面，是给人读的方案文档**。藏进悬停提示的字，客户把原型截图进汇报材料时一个都带不走 |
| **右侧锚点 = 实际产出的各节标题** | 按需节没产就没有对应锚点，**别为了凑节数留空节** |
| **节号跟着实际产出连续编** | 同上 |
| **流程图要渲染成图** | 转成文字描述就是转写。载体里有图就画出来；两处都没有 → 不硬造 |
| **不参与页面清单对照** | 它不是业务页，不在改动清单上，不算虚构菜单项 |
| **不加改造点红点** | 同上 |

**判据一句**：这张表是在模拟产品界面，还是在给人读方案？
**读方案的表不许把字藏进悬停。**

---

## 分量约束

非页面能力每条 4 行；非页面节与全局规则合计超过约 20 行时
（接口详细块不计入），**该压缩的是上游规格的能力说明，不是在这里堆**。

---

## 只出概览页的三种情况

1. **整单没有任何页面条目**——纯接口 / 配置类。
   这类需求过去在原型里一个字都没有，概览页承载了非页面需求之后，它自己就足以当交付载体。
2. **整单全是「截图标注优化点」类小改动**（字段 / 样式 / 显隐级，不新增覆盖态、不需演示交互变化）。
   这类改动没有真实页基线，硬用组件重画会**变形**，画出来的是失真误导品——
   不如只出概览 + 把标注截图放进末节「优化点明细」讲清楚。
   **只要有一页需要真演示（新增区块 / 覆盖态 / 交互状态变化）→ 就不是只出概览。**
3. **对方明确说本单不画页面场景**——他可能已经看过真实页、或改动他自己就说得清。
   **这只免掉「页面场景」，不免概述页。**

### 末节「优化点明细」（仅第 2 种情况）

承载标注截图 + 每个优化点的逻辑（改什么 · 为什么 · 期望）。
**为什么单列**：截图标注类需求的优化点在完整原型里本由页面红点承载，
没有页面原型时，这节就是它唯一的着落处——没有它，客户又回到"手上没东西看"。

# 流水账（log.md）格式约定

> **追加型，只增不改历史；最新在前**（新条目插到 `# log.md` 标题之后）。
> 它的职责是：**切会话后，读一遍顶部就能重建上下文。**

## 单条结构

```markdown
### {YYYY-MM-DD HH:mm} · {阶段} · {类别} · {操作人}

{一句话主旨，20-40 字}

**产物 / 详情**（可选，有则用 bullet 展开）：
- {点 1}
- {点 2}

**状态变化**（可选）：{字段}: {旧值} → {新值}

---
```

- **时间精确到分钟**，取系统真实时间，**不许凭印象填**。
- **主旨 ≤40 字**，禁止在主旨里塞分号嵌入子项——子项一律拆到 bullet。
- **禁用**单行表格里塞 5+ 个分号分隔信息（详情会被淹没）。

## 事件类别（必记范围，缺一不可）

| 类别 | 何时记 | 示例 |
|---|---|---|
| `状态推进` | 完成某一步 / 过闸 / 状态切换 | 完成方案核对，待复审 |
| `PM 反馈` | 提出问题 / 否决方案 / 拍板 | 拍板优先级 P0；否决方案 X 选 Y |
| `AI 决策` | AI 拍板的关键判断 | 类型判定=新功能（依据逐层 why 根因）|
| `被打回方案` | 某方案被推翻 + **原因** | 列表"查看详情按钮" → 改"文字链"，原因：违反列表行详情入口惯例 |
| `资料归档` | 收到新素材 / 已 cp 到 refs/ / 失败补 TODO | 归档客户 Excel 到 process/refs/ |
| `占位变化` | 新增占位 / 占位解除 / 升级风险 | BR-23 覆盖策略已拍板，占位解除 |
| `版本变更` | 达到 bump 粒度的演化（**变更史的唯一权威在这里**）| v1.2：导师上限 10→不限，波及 §一/规格/验收 |
| `资料引用` | 决策时引用了哪条素材 | 引用 refs/Excel 第 X sheet 推断维度树深度 |
| `迭代轮次` | 原型每轮收尾必记（续跑重建上下文的唯一依据）| 第 3 轮：日历订阅交互定稿；待客户：周历默认视图 |

## 续跑纪律

**跨会话续跑，第一件事是读这份 log，不许去翻上一场会话的记录。**

翻上一场的会话记录等于翻录像带重建上下文——那些事实上一场都在上下文里，续跑等于重付一次；
而这份 log 本来就是为这件事设计的。

所以收尾写条目时，除了"改了什么 / 下一步"，**把本轮已拍板的口径也写进去**
（定的判断、放弃的方案、挂账的欠账各一行）。

> **口径是最贵的那部分**：改了什么能从版本历史看出来，
> **为什么这么改只存在于对话里**——不落盘就只能靠翻录像带或重新问一遍。

## 双向校验

任何产物里引用流水账条目作证据（"客户证据来源：log 6-12 答 Q4"）之前：

1. **先 grep 确认该条真实存在**；
2. 存在 → 引用具体时间锚点；
3. **不存在 → 先在 log 追加该条，再回填到产物**。
   **不允许**先在产物写"引用 log…某某答…"然后才补 log——那是事后伪造证据。

**反模式**：规格的证据段引用了一条"log 某日某某答 QX"，而 log 里没有这条 = 凭印象写出的引用，
定稿复审必打回。

## 注意

- 这份账本是**追加型**，行数随需求推进持续增长，**超长是正常态**——
  不要为了"文件太长"去截断它、拆分它或跳过记账。
- 过程 / 决策 / 演进叙述的去处就是这里，**不进需求正文**（正文只写现状）。
